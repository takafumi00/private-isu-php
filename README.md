# private-isu PHP実装のパフォーマンス改善

PR TIMES 学生インターン選考課題として、[catatsuy/private-isu](https://github.com/catatsuy/private-isu) の PHP 実装を動かし、パフォーマンスを改善した記録です。

## 実行環境

- MacBook Air 上で Docker Compose を使って起動（AWS は使用していない）
- アプリケーション: PHP 8.3（php-fpm）+ nginx
- データベース: MySQL 9.7
- ベンチマーカーは Docker で実行

```
docker run --network host -i private-isu-benchmarker /bin/benchmarker -t http://host.docker.internal -u /opt/userdata
```

手元のMacでの計測はブレがあるため（1回ごとに100〜数百程度）、各段階で3回計測し、平均で比較しました。

## 進め方

当て推量で変更しないように、毎回次の流れで進めました。

1. ベンチマーカーを実行し、スロークエリログを `pt-query-digest` で集計して、どのSQLが時間を使っているかを調べる
2. 上位のSQLについて `EXPLAIN` で原因を確かめる
3. 変更は1つずつ行い、それぞれ別のPRにする
4. もう一度計測して、効果があったかをスコアと集計結果の両方で確かめる

## 総括

### ボトルネックの移り変わり

- **最初**: `comments` テーブルを `post_id` で検索するSQLが、DBの実行時間の約97%を占めていた。インデックスがないため、毎回約10万行を全件スキャンし、最大3行しか返していなかった。インデックスを追加して、スコアが約19倍になった（PR #2）
- **次**: トップページで、20件しか表示しないのに投稿を毎回約1万件取得していた。必要な20件だけを取得するように変えて、約10%向上した（PR #3）。単純に `LIMIT 20` を付けるだけだと、BANされたユーザーの投稿が除外されて20件に満たず、ベンチマーカーのチェックに失敗するため、`users` と JOIN して絞り込んだ
- **その後**: DBはボトルネックではなくなった

### スコアが変わらなかった変更から学んだこと

PR #4 と PR #5 は、狙ったSQLは確実に速く・少なくなったのに、スコアは変わりませんでした。

- PR #4 では、対象のSQLの見積もりコストが約21分の1になった。しかし `pt-query-digest` の集計で、ベンチ中のMySQLは平均して同時に0.54個のSQLしか処理しておらず（`0.54x concurrency`）、余裕がある状態だった。DBに余裕があるときにDBを速くしても、全体は速くならないことがわかった
- そこで「PHPとDBの往復が詰まっている」と予想して、PR #5 でN+1問題を解消した。ベンチ1回あたりのSQLの総数は約21.1万回から約9.5万回に減ったが、スコアも、成功したリクエスト数も変わらなかった。この予想は外れていた

現時点では、PHP-FPM の同時処理数（Docker イメージの初期設定では5）がボトルネックになっていると考えています。画像は1枚ごとにPHPがDBから読み出して返しており（最後の計測でDB時間の42%）、少ないワーカーが画像配信でふさがっている可能性があります。

「詰まっていない場所を速くしても全体は速くならない」こと、そして「どこが詰まっているかを、計測結果を根拠に判断する」ことの大切さを、身をもって学びました。

### 計測について

- 連続でベンチマーカーを実行すると、手元のMac（ファンのない MacBook Air）が熱を持ち、タイムアウトが増えてスコアが下がった。休ませてから計測し直した
- PR #3 以降、負荷をかける前の確認段階で `POST /login` がタイムアウトし、`"pass":false` になる回がたびたびあった。表示内容のエラーではなくタイムアウトのみであること、初期状態の計測でも `POST /login` のタイムアウトは毎回発生していたことから、コード変更による不具合ではなく、ログイン処理そのものが遅いことが関係していると考えている。原因は特定できていない
- 失敗した回も含めて、各PRの description に記録した

## 今後の改善案

| 改善案 | 理由 |
|---|---|
| 画像をファイルとして保存し、nginx から直接配信する | 画像の読み出しがDB時間の42%を占めており、PHPのワーカーを画像配信から解放できる |
| PHP-FPM のワーカー数を増やす | 同時に5つしか処理できないことが、現在のボトルネックだと考えている |
| パスワードのハッシュ計算を PHP の `hash()` 関数に置き換える | 現在はログインのたびに外部コマンド（`openssl`）を起動している。`POST /login` のタイムアウトとの関係も疑っている |
| `comments` の `user_id` にインデックスを追加する | ユーザーページで、コメントを全件スキャンしているSQLが残っている |
| コメント取得をウィンドウ関数でまとめる | PR #5 の後も、コメント本体は投稿ごとに取得している |
| スロークエリログを止める | 計測のための設定なので、計測が終わったら不要 |
